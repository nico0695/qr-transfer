## What's done in Stage 5

- **`AppShell`'s API changed** from a `stage: ReactNode` prop to `StageSlotContext` /
  `useStageSlot()` (`src/components/app/AppShell/StageSlotContext.ts`, exported from
  `AppShell/index.ts`). AppShell renders an empty `<div>` for the stage pane and provides its DOM
  node via context; screens rendered inside `compose` call `useStageSlot()` and
  `createPortal(<Stuff/>, stageNode)` to place content into `stage` — this is _why_: a screen owns
  a single camera-lifecycle hook instance, which can't be split into two separately-mounted
  components without either duplicating the hook (two cameras) or lifting all its state up to
  `App.tsx` (which shouldn't know about camera internals). Portal is the standard React answer to
  "one component, two DOM locations." Verified working for both the QR canvas and the camera
  viewfinder via manual browser testing (screenshots taken, no console errors).
- **New components** (`src/components/app/`): `TextEditor` (plain mode — Card, header
  title+Copy/Clear, textarea, footer counter), `OpticalStage/QrDisplay` (empty/ready per
  docs/DESIGN_SYSTEM.md §5.8), `OpticalStage/CameraScanner` (viewfinder chrome per §5.9),
  `ResultPanel` (§5.11, built on the `Feedback` primitive).
- **`src/hooks/useCopy.ts`** extracted (copy-to-clipboard + self-resetting feedback). Deliberately
  did **not** touch or delete `src/components/CopyButton.tsx` — `LargeTextEditor.tsx` and
  `ReceivedContent.tsx` still import it and haven't been redesigned yet (Stages 6/8); removing it
  now would break those screens. It gets removed once nothing imports it anymore.
- **`QRGenerator.tsx` / `QRScanner.tsx` rewritten** onto the new components. The camera lifecycle
  in `QRScanner.tsx` (the `finished` flag, `session` counter, `stopScanner()` in the effect
  cleanup, the two-effect shape — camera list, then start/stop) is **preserved verbatim** from the
  pre-Stage-5 version — this was a hard constraint (macro-plan Stage 5 "Constraints"), not touched
  beyond moving the JSX around it.
- Added i18n keys: `liveLabel` (en/es) for the camera "live" badge. Reused existing `sourceText`/
  `sourceFile`/`cameraLabel`/etc. where they already existed — did not duplicate them (Stage 4's
  review caught exactly that mistake once already; avoided repeating it).
- `App.tsx` passes `onShowStage={() => setView('stage')}` to `QRGenerator` for its mobile
  "Show QR" button (now a `Button` primitive, scoped to hide ≥900px via
  `src/components/QRGenerator.module.css`, since the old `.mobile-only` legacy class is tied to the
  old 760px breakpoint, not the new 900px one).

## Anything risky to know before resuming

- The `StageSlotContext` change to `AppShell` is a **public API change** from what Stage 4
  shipped. Nothing else consumes `AppShell` yet except `App.tsx` (already updated), so this is
  safe, but worth remembering when Stages 6–8 wire up Large Transfer's send/receive screens —
  they'll use the same `useStageSlot()` pattern, not a `stage` prop.
- `QrDisplay`'s canvas is only mounted in the DOM while `!isEmpty && !error` (unlike the original,
  which kept a hidden canvas mounted at all times). This was a deliberate simplification, verified
  working (QR renders correctly after typing), but if a subtle timing bug ever shows up around the
  QR canvas specifically, this is the first place to look.
